> 本项目仅供个人学习和研究计算机视觉、桌面自动化技术使用。使用时请遵守游戏及相关平台的使用规则。

此声明不替代许可证，也不表示已获得游戏官方授权。
#置顶
启动前确认：代码版本与目录正确，解释器、依赖和配置符合要求，所需权限与服务可用，输入状态正确。桌面自动化另需检查前台窗口、分辨率和缩放。

故障记录应包含：环境、复现步骤、预期与实际结果、完整错误、已尝试操作及结果。

已知案例：视觉助手识图正常但鼠标操作失败，本机以管理员身份运行后恢复。遇到类似现象，优先检查权限条件。

### 启动前

1. 已在目的地篝火旁（人物界面），不要打开地图或菜单。
2. 4K 全屏，游戏在前台；助手与游戏使用相同权限（识别正常但不动时，右键 `launch_admin.bat` 以管理员运行）。
3. 角色朝向固定；运行中不要动鼠标、不要按方向键旋转视角。

### 每轮流程

| 步骤 | 动作 | 确认条件 |
|---|---|---|
| 1 | 按 M（已在地图则跳过） | 识别到地图标题 |
| 2 | 根据道路与建筑上下文定位并点击指定篝火 | 本轮重新点击，最新选中位置与目标一致且传送按钮有效 |
| 3 | 点击“传送” | 回到人物界面并看到 F「稍作休息」 |
| 4 | 按 F | 篝火菜单出现，识别到“刷新怪物” |
| 5 | 点击“刷新怪物”，0.8 秒后按 Esc | 回到人物界面 |
| 6 | W 约 3.0 秒到图5 → A 约 1.8 秒到图6 → S 约 2.0 秒到图7后松开 | W/A/S 均属于走位；固定时长执行，检查地图/菜单及黑屏，不校验 UID |
| 7 | S 松开后开始战斗，立即轻点一次左 Shift，随后每 2 秒一次，共 40 次 | 从 S 实际松开起计算 80 秒；战斗期间不按 S |
| 8 | 按 M，重新定位同一篝火并传送 | 本轮完成；未到轮数则继续按 F |

指定 `max_loops` 时，完成对应轮数的最后一次传送后停在篝火旁，不再按 F。`max_loops` 默认 0（无限循环），两个任务共用。

W/A/S 是到图7的走位，S 只按约 2 秒。S 实际松开成功后才开始 80 秒战斗，战斗期间**不再截图比对**；首次 Shift 立即安排，随后按实际发送时间每隔 2 秒一次。50ms 轮询检查停止和前台，单次 Shift 默认按住 80ms。停止、切出或异常会释放本程序按住的键。系统延迟导致无法在原窗口内完成 40 次时明确暂停，不追赶连点。图5/6/7按固定路线时长定位，当前没有独立的图7地标识别。

### 识图方式

- 画面统一归一化到 1499×843 参考画幅；这不等于支持任意游戏内地图缩放。普通按钮阈值和地图上下文阈值、唯一性及分区一致性参数见 `assets999/templates.json`。
- 地图：卷轴确认地图页，带遮罩的道路与建筑上下文唯一匹配指定地点。玩家箭头、地图文字和选中圈均不用于定位；白圈只在点击后核验已定位目标，右侧“传送”按钮另行匹配。
- 篝火菜单：底部“休整”确认菜单身份；刷新按钮由固定文字、原始图标或高亮变体确认，未识别到有效按钮就不点击。
- 人物界面：取消 UID 模板加载和匹配；非黑画面未命中地图或篝火菜单时按人物界面处理。此分类较宽松，不代表已完成传送，F 仍须提示校验。
- 到达：匹配 F「稍作休息」提示，未出现不按 F。
- 面板是否打开：匹配“传送”文字或右上角关闭按钮。

## 鼠标定位修复与单步验收（2026-10-18）

新增单步入口，先验证Windows是否真正移动光标、接收点击，再运行完整循环。单步入口不会启动G5任务循环，也不会自动从“前往”继续点击“开始匹配”。默认只移动；只有显式`--click`才允许一次点击。左Ctrl可中止；每次结束都释放本程序按住的键。

先关闭旧助手和旧 Lua 循环，避免多个输入来源。用户此前已通过管理员运行恢复游戏输入；开发、读代码与离线测试通常无需管理员，游戏已提升权限时通过 `launch_admin.bat` 运行助手。输入进程应具有与游戏相应的权限，程序不自动提权。先用单步检查确认游戏实际响应，再验收完整循环；输入 API 返回成功不等于游戏接收了动作。

`input_check.bat`菜单先选3验证桌面收到单击，再选5验证单次前往后出现匹配页。也可在项目目录以相同权限执行：

```bat
.venv\Scripts\python.exe -X utf8 app.py --input-check inspect
.venv\Scripts\python.exe -X utf8 app.py --input-check desktop --move-only
.venv\Scripts\python.exe -X utf8 app.py --input-check desktop --click
.venv\Scripts\python.exe -X utf8 app.py --input-check game --move-only --target go
.venv\Scripts\python.exe -X utf8 app.py --input-check game --click --target go --timeout 20
```

`inspect`只读，仅保存脱敏的结构化环境报告，不截图整个桌面。`desktop`创建独立靶窗，移动后核对实际物理位置；点击模式必须由靶窗的实际左键事件回调确认才报告`desktop_click_received`。请先把靶窗放在要验证的显示器上；默认靶窗在主屏左上方。检查开始后请等待自动完成，避免手动点靶心造成接收证据混淆。

`game`切换到游戏后，连续识别正确页面，定位“前往”；加`--click`只点击一次，随后只观察匹配页。识别到匹配页才报告`go_response_match_verified`。位置到达只报告`game_move_verified`，不会把输入API成功当作游戏已接受点击。若15秒内无法识别响应，可以显式调整`--timeout 20`，不会自动补点。

若已手动停在匹配页，可以单独检查开始匹配按钮：

```bat
.venv\Scripts\python.exe -X utf8 app.py --input-check game --move-only --target match
.venv\Scripts\python.exe -X utf8 app.py --input-check game --click --target match --timeout 60
```

`--target match --click`会实际开始一次匹配；只有识别到匹配页才执行，之后只观察，不执行退出战场等循环动作。响应超时显示`click_sent_response_unconfirmed`，退出码为1，保留证据；未知画面不能证明已进入战场。`--start-delay`默认2秒，允许0–10秒；`--timeout`允许1–120秒。

每次创建`diagnostics/input_check_UTC时间/report.json`，包含环境、实际输入跟踪、目标及回读位置、点击接收事件、识别结果和截图文件名。按下前再次截图核验页面和按钮位置，变化就取消。异常也保留报告；截图不可用会明确记录错误，不能伪称完成截图验收。可用`--report-dir "D:\检查报告"`改变输出位置。

定位日志现在保留Windows API立即返回的错误码/文本、调用参数、移动前和立即/20/60/150毫秒位置、虚拟桌面、ClipCursor、前台窗口、输入桌面和进程权限。单步检查在检测到线程不在输入桌面或无法确认时禁止移动/点击；完整循环遇到明确桌面不符或助手权限低于游戏时也会暂停；不会自动切换桌面或解除游戏的光标限制。

原始日志的双屏范围为`(-2560,0)–(3840,2160)`，目标`(3379,2028)`对应归一化`(60824,61559)`，该换算与日志一致。旧版没有保存物理定位失败的错误码，也没有移动前和即时光标位置，因此仍不能从旧日志判定是限制、权限或游戏回移。此修复提供能区分这些原因的证据，不把150%缩放直接认定为原因。

工具的隔离桌面可能无法访问用户输入桌面；这种失败不能代替用户桌面的实机验收，也不能证明历史输入失败具有相同原因。请在交互桌面检查报告中的桌面状态和实际页面响应。

若原`.venv`提示解释器拒绝访问，说明该虚拟环境引用的Python不可用。`input_check.bat`会保留此错误；可以在命令行先设置`set "YIHUAN_PYTHON=D:\python3.13\python.exe"`后运行批处理，前提是该Python已安装项目依赖。不要把解释器启动失败当作输入测试失败。

## 0.3前往点击无响应

这版针对“等待匹配页超时、画面仍在前往”的故障补充定位和有限恢复。0.2只知道Windows接受了输入调用，没有记录实际鼠标位置；不能仅凭超时断定是多屏坐标还是游戏没有响应输入。

- 鼠标移动后等待150毫秒，使用GetPhysicalCursorPos回读实际物理坐标；与按钮目标位置相差超过4像素时，用SetPhysicalCursorPos纠正一次。纠正后仍不符就取消点击并暂停。
- 日志记录目标位置、实际位置和定位方式。鼠标左键按住100毫秒后松开。
- “输入已发送”与“匹配页已出现”分别记录；没有看到匹配页就不会点击开始匹配。
- 前往点击3秒后，只有连续识别到活动页且动作前最新截图仍匹配时，才补点一次；两次尝试共用原来的15秒总等待上限。开始匹配、确认和Esc不自动补发。
- 故障JSON增加最近输入的定位详情、最近12次已发送动作及按钮识别坐标；同时保存最近一次动作前画面和暂停时画面。
- 保留0.2的窗口选择、多显示器和DPI修复。依赖与config.json字段均未改变。

更新：退出旧助手，解压新版，覆盖原目录的源码和assets即可；保留原来的.venv及你修改过的config.json。重新启动后标题应显示0.3。

若仍不动，请提供本次运行的logs/assistant.log，以及diagnostics里同一时间的startup JSON、故障JSON和PNG。鼠标位置核对正确只证明系统光标到达按钮，不能证明游戏接收了点击。

## 启动

1. 解压整个压缩包，建议放到个人可写目录，例如 `D:\YiHuanVision`，不要在压缩包内直接运行。
2. 若尚未安装Python，安装 [Python 3.12 64位](https://www.python.org/downloads/windows/)，保留Python Launcher，或勾选Add Python to PATH。
3. 双击 `launch.bat`。第一次会在本目录创建 `.venv` 并联网安装依赖；后续直接启动界面。安装失败会保留窗口显示原因。
4. 关闭G HUB里的旧Lua循环。G5先取消其他宏/配置切换，保持默认前进侧键；如果系统监听不到，可把G5绑定为F8，助手也接收F8。
5. 游戏设置为3840×2160全屏，手动停在活动页，确保右下角“前往”可见。
6. 点击助手的“开始”，或者在游戏前台按G5。助手最小化，切回游戏，等待1秒后开始识别。
7. 左Ctrl全局停止；切回助手也可以点击“停止”。停止会释放本程序按下的Esc/鼠标左键。再次启动前回到活动页。

默认无限循环。若先试一轮，在 `config.json` 中把 `"max_loops": 0` 改成 `"max_loops": 1`，保存后再启动任务。

## 执行规则

| 画面或阶段 | 动作 |
|---|---|
| 活动页 | 连续识别到“前往”和活动标题，核对鼠标位置后点击；3秒后仍为活动页时最多补点一次 |
| 匹配页 | 识别到VS和“开始匹配”，点击一次 |
| 加载 | 持续观察，预计32秒；提前出现胜利也直接处理 |
| 战场 | 从确认进入战场起按当前 `battle_watch` 配置观察（本地为 14 秒），期间优先检查结算 |
| 胜利/失败结算 | 按一次Esc，等待有效的离开确认框，再确认 |
| 观察时长后仍在战场 | 按一次Esc，确认退场；至少间隔1秒，且识别到结算，再执行结算离开 |
| 返回 | 预计12秒；确认活动页出现才计为一轮并循环 |

每个画面默认连续识别2次，识别间隔约0.2秒；动作前再核对一次最新画面。没有看到对应确认框就不点击确认。状态没变化时不会持续重复按Esc或反复点击匹配。

2秒、32秒、12秒是界面转换的预期耗时。战场观察时长（当前本地配置 14 秒）与 1 秒最短间隔是实际计时规则，不恢复历史默认值。实际加载时间由画面判断，不通过固定32秒假定已进入战场。

## 日志、暂停和截图

- 界面显示当前阶段和滚动日志；完整日志在 `logs/assistant.log`，自动轮换。
- 找不到游戏、游戏离开前台、窗口位置/分辨率改变、输入被拒绝，任务会暂停。
- 匹配页等待上限15秒，加载上限90秒，确认框8秒，结算20秒，返回活动页45秒。可在配置里调整。
- 加载与返回期间允许黑场；在其他阶段持续15秒无法识别会暂停。
- 运行异常时，保存最近一次有效捕获的游戏区域到 `diagnostics/时间.png`，以及最近一次尝试动作前的 `时间_before_input.png`；同名 JSON 包含阶段、识别得分、按钮坐标、最近输入详情和最近 12 次已发送动作。图像和结构化报告保存前脱敏，识别仍使用原始内存帧。未捕获过画面时只记日志。
- 启动阶段也有 `diagnostics/startup_时间.json`，即使尚未开始截图，仍可定位选中了哪个窗口、读到了多大尺寸。该文件保存前做通用字段、路径和邮箱脱敏；未知位置的任意个人信息不保证自动识别，分享前仍应检查。
- 任务暂停后不会自动重新启动。检查界面、回到活动页，再启动。
- 多开助手会被拒绝；G5只在游戏前台触发启动。原Lua循环必须保持关闭。

## 截图方式和配置

默认 `capture_backend` 为 `auto`：主显示器先尝试DXGI/DXcam，初始化不成功改用MSS；其他显示器默认使用MSS。若截图持续黑屏或识别异常，先看诊断PNG：

- PNG是正确游戏画面：通常需要调整模板；可把诊断PNG、JSON、日志提供给开发者。
- PNG是黑屏：可将 `capture_backend` 改成 `"dxcam"` 或 `"mss"`，重新启动任务测试。
- 显式使用DXcam时，`dxcam_device_idx` 和 `dxcam_output_idx` 指定显卡与显示器输出，默认均为0；尺寸必须与4K游戏一致。多显示器配置需确认输出选择正确。

程序默认匹配标题包含“异环”、Neverness或独立单词NTE的窗口。若实际标题不同，修改 `window_title_regex`。点开始后会检查前台游戏和截图尺寸，无法切回时会暂停并提示手动切回后按G5。

输入使用Windows SendInput。游戏与助手需使用相同完整性级别；本版在输入前检查明显的权限差异，并记录原生API即时错误、鼠标限制和桌面状态。定位失败会取消点击，权限相同也不能代替实际页面响应验收。

咔呲识别模板取自你提供的修订 PDF。原图1499×843，运行时将4K画面归一化到这个参考画幅后在局部区域匹配；不依赖角色、名字、段位和奖励数量。PDF缩放图的离线通过不代表真实4K截图一定通过，首轮仍需实机校准。

## 只读识图检查

在项目目录打开命令行：

```bat
.venv\Scripts\python.exe app.py --check-image "你的游戏截图.png"
```

只输出场景、匹配得分与按钮中心，不发出键盘鼠标操作。`assets/templates.json` 定义模板位置、局部搜索范围和阈值；只有需要校准时才修改。

## 在Windows生成EXE

双击 `build_exe.bat`。它会安装PyInstaller并生成：

```text
dist\YiHuanVision\YiHuanVision.exe
```

复制时保留整个 `dist\YiHuanVision` 文件夹。该版本目录包含运行依赖，目标电脑不必另外安装Python。生成的EXE依然需要在实际游戏里验证。当前交付的是源码和启动/构建脚本，不包含已构建的Windows EXE。

## 验证与扩展

```bat
.venv\Scripts\python.exe -B tools/run_checks.py
```

离线测试使用输入替身，不向 Windows 发送真实游戏输入。覆盖指定地图点、基准缩放下平移、已支持截图格式、遮挡与重复候选拒绝、玩家标记变化、错误选中圈、旧面板及动作前地图变化，并回归咔呲、停止和释键。详见 `TEST_REPORT.md`。

实机验收按最新 MD：先单步点击指定点，核对实际选中与传送到达，再核对 F/刷新/Esc、原走位、80 秒 40 次 Shift、每轮重新定位、左 Ctrl 停止及异常释键。分别报告本地修改、本地提交、远端推送和游戏实测，不把离线通过写成游戏实测；不沿用旧测试数量。

代码分工：

- `yihuan/core.py`：咔呲任务流程、阶段和动作。
- `yihuan/tasks.py`：脚本注册表；每个任务分别提供流程和识别器。
- `yihuan/vision.py`：模板匹配、稳定帧与动作前校验。
- `yihuan/windows.py`：Windows窗口、截图和输入。
- `yihuan/runtime.py`：任务线程、停止、日志、异常截图。
- `yihuan/ui.py`：脚本选择、开始、停止、状态和日志。

后续任务实现相同任务接口，在tasks.py里注册自己的流程和识别器，即可出现在脚本下拉框。输入适配可按其他任务需要扩充，首版没有预设其他任务的具体操作。
